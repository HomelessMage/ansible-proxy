# ansible-proxy

Свой VPN-сервер одной командой: VLESS + XHTTP (packet-up) за nginx с TLS, панель 3x-ui в Docker.

Снаружи сервер выглядит как обычный сайт: сертификат Let's Encrypt, HTTP/2, страница-заглушка,
на чужое имя сервера (SNI) соединение рвётся. Xray и панель управления наружу не смотрят —
они слушают только 127.0.0.1.

## Быстрый старт (по шагам)

### Что понадобится

- **Компьютер с Linux или macOS** (на Windows — через WSL). С него запускается Ansible, на сервер
  ничего ставить руками не нужно.
- **VPS с Debian 13** у любого зарубежного хостера, от 1 vCPU и 1 ГБ памяти, с публичным IPv4.
  Проверь правила хостера: часть из них запрещает VPN или отдельные протоколы.
- **Домен или поддомен**, которым ты управляешь. Подойдёт и бесплатный поддомен, например на
  [FreeDNS](https://freedns.afraid.org). Не заводи все свои серверы на одном домене: по нему их
  легко найти все сразу.

### 1. Установить Ansible и git на свой компьютер

```sh
# Debian / Ubuntu
sudo apt install ansible git
# Arch
sudo pacman -S ansible git
# Fedora
sudo dnf install ansible git
# macOS (Homebrew)
brew install ansible git
```
Проверка: `ansible-playbook --version` должен вывести версию.

### 2. Скачать репозиторий

```sh
git clone https://github.com/HomelessMage/ansible-proxy.git
cd ansible-proxy
```

### 3. SSH-ключ

Если ключа ещё нет (`ls ~/.ssh/id_ed25519.pub` пишет «No such file»), создай его:
```sh
ssh-keygen -t ed25519
```
Положи ключ на сервер (спросит пароль root, который дал хостер):
```sh
ssh-copy-id root@<IP сервера>
```
Проверь, что пускает без пароля: `ssh root@<IP сервера>` → должна открыться консоль сервера.
Выйти — `exit`.

> После установки вход на сервер будет **только по ключу**, пароль перестанет работать.
> Не потеряй `~/.ssh/id_ed25519`.

### 4. Направить домен на сервер

В панели DNS своего домена создай **A-запись**: имя — твой (под)домен, значение — IP сервера.
Подожди пару минут и проверь:
```sh
dig +short <домен>      # или: nslookup <домен>
```
Должен вернуться IP сервера. Без этого не выпустится сертификат.

Теперь зайди на сервер уже по домену — один раз, чтобы SSH запомнил его ключ:
```sh
ssh root@<домен>
```
На вопрос «Are you sure you want to continue connecting» ответь `yes`, потом `exit`.

### 5. Указать свой сервер

```sh
cp inventory.example.yml inventory.yml
```
Открой `inventory.yml` и замени `node1.example.org` на свой домен:
```yaml
all:
  vars:
    ansible_user: root
  hosts:
    vpn.example.org:
```

### 6. Запустить

```sh
ansible-playbook site.yml
```
Первый запуск идёт 3–5 минут. В конце должно быть `failed=0`:
```
PLAY RECAP ****
vpn.example.org : ok=61  changed=34  unreachable=0  failed=0 ...
```

### 7. Подключиться

Ссылка для подключения лежит в `credentials/<домен>/links.txt`:
```sh
cat credentials/vpn.example.org/links.txt
```
Это строка `vless://…`. Скопируй её и импортируй в клиент с поддержкой XHTTP — на Xray-core,
например v2rayN (Windows, Linux, macOS) или v2rayNG (Android): «Импорт из буфера обмена».
На роутере с OpenWrt — podkop с [podkop-engine](https://github.com/podkop-net/podkop-engine)
(стоковый sing-box XHTTP не умеет).

Готово. Дальше — как добавить ещё людей, зайти в панель и что ещё можно настроить.

### Если что-то пошло не так

| ошибка | что проверить |
|---|---|
| `UNREACHABLE` / `Permission denied (publickey)` | шаги 3–4: `ssh root@<домен>` должен пускать без пароля |
| `Host key verification failed` | шаг 4: один раз зайти `ssh root@<домен>` и ответить `yes` |
| падает «Выпуск сертификата Let's Encrypt» | шаг 4: `dig +short <домен>` возвращает IP сервера; у хостера не закрыт порт 80 |
| падает на пакетах (`apt`) | на сервере Debian 13? `cat /etc/os-release` |
| клиент не подключается | ссылку брать из `links.txt` целиком; в клиенте должен быть XHTTP |

Повторный запуск всегда безопасен: плейбук меняет только то, что разошлось с описанием.
Поэтому после исправления просто запусти его ещё раз.

# Справочник

## Ещё одна нода

1. Как в быстром старте: Debian 13, ключ у root, A-запись домена.
2. Добавить домен в `inventory.yml`:
   ```yaml
   all:
     hosts:
       node1.example.org:
       node2.example.org:
   ```
3. Запустить только для неё (`-l` — ограничить одним хостом):
   ```sh
   ansible-playbook site.yml -l node2.example.org
   ```
4. Результат — в `credentials/<домен>/`:
   - `links.txt` — vless-ссылки клиентов;
   - `panel.txt` — как зайти в панель.

Повторный запуск безопасен: меняется только то, что разошлось с описанием.
Проверить без изменений: `ansible-playbook site.yml -l <домен> --check --diff`.

## Добавить людей (клиенты VPN)

Общий список для всех нод — `xui_clients` в `group_vars/all.yml`.
Свой список для одной ноды — файл `host_vars/<домен>.yml`:
```yaml
xui_clients:
  - home-router
  - friend-router
  - phone
```
Каждому человеку или устройству — своя строка: так любого можно отключить, не трогая остальных.
Затем:
```sh
ansible-playbook site.yml -l <домен> --tags xui
```
Плейбук досоздаст недостающих клиентов и перепишет `links.txt`. Имя из списка — только метка
(комментарий в панели); в панели и в ссылке клиент получает случайное имя вида `node1-k3x9q0b2mz`.
UUID и случайное имя постоянные (выводятся из секрета ноды и метки). Удалять или отключать
клиента — в панели.

## Панель 3x-ui

Панель наружу не открыта, заходить через SSH-туннель:
```sh
ssh -N -L 5223:127.0.0.1:5223 root@<домен>     # окно держать открытым
```
Потом в браузере — адрес из `credentials/<домен>/panel.txt` (там же логин и пароль).
В панели видно трафик клиентов, их можно отключать и удалять.

## Частичный запуск

| тег     | что                                                              |
|---------|------------------------------------------------------------------|
| `base`  | hostname, пакеты, автообновления, sshd (только ключи), nftables  |
| `root`  | zsh + oh-my-zsh (darkblood), ключи root                          |
| `nginx` | nginx, сертификат, заглушка                                      |
| `xui`   | 3x-ui, инбаунд, клиенты, links.txt                               |

Пример: `ansible-playbook site.yml -l <домен> --tags nginx`.

## Настройки (`group_vars/all.yml`, переопределяются в `host_vars/<домен>.yml`)

- `ssh_allow` — пусто: 22 открыт всем; иначе список IPv4, например `[1.2.3.4/32]`;
- `ssh_keys` — ключи root (по умолчанию `~/.ssh/id_ed25519.pub`);
- `xui_image` — версия 3x-ui; обновление: поменять тег и запустить с `--tags xui`;
- `zsh_theme`, `zsh_plugins`.

## Страница-заглушка

По корню сайта открывается заглушка. Своя для ноды — файлы в `site/<домен>/` (`index.html` и что
угодно ещё), они копируются как есть. Если каталога нет — стандартная страница nginx из Debian.
Не используй одну и ту же самодельную страницу на нескольких нодах: по ней ноды связываются между
собой.

## Локальные файлы (в .gitignore)

`inventory.yml`, `host_vars/`, `credentials/`, `site/` — в них реальные домены и секреты.

## Секреты

`credentials/<домен>/` создаётся при первом запуске и есть только локально (в .gitignore):
путь XHTTP, логин/пароль/путь панели, seed UUID. **Не терять**: без `client_seed` и `xhttp_path`
плейбук сгенерирует новые, и ссылки клиентов перестанут работать.

## Не автоматизировано

Особенности сети хостера (например, NetworkManager вместо ifupdown).
